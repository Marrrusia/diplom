# Интеллектуальный анализ покрытия требований

Версия **0.2.0**: выделение и отдельная смысловая экспертиза, связи с условиями,
сохранение спорных предложений и ручная сверка полноты. Правила выделения по
фиксированным фразам удалены. См. [новый механизм](docs/extraction_v2.md)
и [корпус для проверки моделей](examples/validation_corpus.json).
Фактические результаты: [проверки 0.2.0](docs/validation_v2_results.md).

Настольное приложение на Python 3.11+ и PySide6 для ВКР
«Разработка инструмента интеллектуальной поддержки анализа покрытия требований
и генерации тест-кейсов с использованием больших языковых моделей».
Интерфейс на русском языке; основной целевой сценарий — PyCharm на Windows 11.

Приложение импортирует требования и тесты, выделяет проверяемые элементы,
анализирует покрытие, предлагает недостающие тесты и поддерживает ручную проверку.
Проекты сохраняются в SQLite, отчёты экспортируются в XLSX. Для LLM доступны
бесплатный локальный Ollama и OpenAI-совместимые серверы. Платный сервис не обязателен.

## Быстрый запуск на Windows 11

1. Установите [Python 3.11+](https://www.python.org/downloads/windows/)
   и [PyCharm](https://www.jetbrains.com/pycharm/download/?section=windows).
2. Распакуйте проект и откройте папку `diplom` в PyCharm.
3. Создайте интерпретатор Virtualenv `.venv` на базе Python 3.11+.
4. В терминале проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe main.py
```

Для установки без заранее созданной среды доступен `scripts/setup_windows.ps1`.
Для проверки — `scripts/verify_windows.ps1`. Подробности и решения типичных
ошибок: [инструкция Windows](docs/windows11.md).

## Первый рабочий сценарий

1. Для локального анализа установите [Ollama](https://ollama.com/download/windows)
   и выполните `ollama pull qwen2.5:7b`.
2. В «Настройки LLM» выберите `ollama`, адрес `http://localhost:11434`, модель
   `qwen2.5:7b`. Ключ не требуется.
3. Импортируйте `examples/requirements.txt` в «Требования».
4. Выделите элементы в «Проверяемые элементы» и проверьте их смысл и цитаты.
5. Импортируйте `examples/test_cases.csv` в «Тест-кейсы» и сопоставьте колонки.
6. Выполните анализ в «Матрица покрытия». Просмотрите каждое обоснование и
   примите только подтверждённые вами связи, указав причины.
7. Сохраните проект через **Ctrl+S**, отчёт — через **Ctrl+E**.

Для генерации полного первоначального набора не импортируйте существующие
тесты. Для дополнения сначала завершите проверку покрытия. Предложения модели
не увеличивают покрытие автоматически. Подробнее: [руководство](docs/user_guide.md).

## Структура

```text
main.py                  запуск из PyCharm
pyproject.toml           зависимости, entry point, pytest
reqtest/
  ui/                    окна, редакторы, фоновые потоки, представление
  models/                строгие модели Pydantic
  importers/             TXT, DOCX, CSV, XLSX
  llm/                   HTTP-клиент Ollama / OpenAI API
  services/              анализ, покрытие, генерация, ручная проверка
  storage/               атомарное сохранение SQLite
  exporters/             шестилистовый XLSX-отчёт
examples/                примеры для демонстрации
scripts/                 установка и проверка Windows, GUI smoke test
tests/                   модульные и интеграционные тесты
.github/workflows/       подготовленные проверки Windows / Ubuntu
```

SQLite входит в стандартную библиотеку Python. API-ключ и настройки сеанса
не записываются в файл проекта. Переменная `REQTEST_LOG_DIR` позволяет выбрать
каталог журнала; по умолчанию используется `%USERPROFILE%\.reqtest\logs`.

## Проверки в Linux

```bash
python -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q
.venv/bin/python -m pip check
```

Автоматические тесты используют подменённые ответы LLM, а не настоящую модель.
Windows 11, качество выбранного Ollama и работа на встроенном ПО проверяются
отдельно. Подготовленный GitHub Actions не является свидетельством уже
выполненной проверки Windows. Приложение оценивает содержание тестов,
а не запускает их на целевом устройстве.
