# Выделение 0.3.0: один запрос и текстовая применимость

Версия заменяет обязательную двухступенчатую экспертизу 0.2.0. Для каждого
требования выполняется один запрос. Повтор нужен при ошибке соединения, неверном
JSON или отсутствующей в исходнике цитате; всего не более трёх попыток.

Модель возвращает четыре поля элемента:

- `type` — одна из шести категорий, подходящих к смыслу аспекта;
- `description` — один проверяемый аспект;
- `source_fragment` — точная непрерывная цитата;
- `applicability` — условия ветви, входное событие и режим текстом.

ID элементов и требования назначает приложение. `source_ids`, `condition_ids`
и граф отрицаний в ответе модели не нужны. Прежние связи старых проектов
поддерживаются для совместимости, но новые ответы их не создают. Текстовая
применимость показывается в редакторе/просмотре, сохраняется в SQLite, экспортируется
в Elements и передаётся анализу покрытия и генератору в составе элемента.

В подсказке разъяснены категории и приведён один общий пример разделения записи
результата и возврата кода. Категории не надо заполнять все: вызов входной функции
не означает цикл или искусственный «режим обработки». Функциональные правила
по конкретным именам требований не добавлены.

Программа проверяет структуру, наличие цитаты и подозрительные новые кодовые
имена/числа. Спорный литерал блокирует только соответствующий кандидат.
Несовпадение формулировки не заменяется выдуманной цитатой. Если исправить все
цитаты не удалось, лучший пригодный частичный ответ остаётся видимым вместе
с диагностикой отсутствующих фрагментов. Точное совпадение цитаты не доказывает
правильность категории, полноту или атомарность.

Отдельная смысловая экспертиза больше не запускается и не блокирует все элементы.
Результат остаётся предложением модели. Полнота считается непроверенной до ручной
сверки с исходником. При необходимости разделите составной элемент через редактор
и кнопку добавления, исправьте категорию или контекст; затем примите/отклоните
предложения. Это не подтверждает автоматически связи покрытия.

## Диагностика

Для каждой попытки в SQLite сохраняются ответ модели, конкретная ошибка и имя
модели. В «Проверяемых элементах» есть «Сохранить диагностику выделения»: отдельный
JSON содержит исходники, ответы и замечания. Настройки сервера и API-ключ туда не
включаются. При полном отказе исходный проект не меняется, а сообщение ошибки
содержит причину и последний ответ модели.

## Проверка настоящей модели

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_extraction.py --model qwen2.5:7b --output work\model-evaluation.json
```

В этом запуске эталоны не отправляются модели. Отчёт позволяет сравнить ответы
с текстом и иллюстративными эталонами. `--fixture` проверяет только обработку
подменённых ответов и не измеряет качество LLM. Прогон может занимать минуты на
требование, особенно на CPU. Изменение модели/оборудования влияет на результат.

Для запуска приложения распакуйте новую папку, выберите интерпретатор Python
3.11+ с зависимостями проекта и запустите main.py. В заголовке должна быть 0.3.0.
Существующий .sqlite можно открыть; после нового выделения прежние связи покрытия
сбрасываются, а отклонённые тесты сохраняют своё решение об отклонении.
