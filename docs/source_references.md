# Источники по идентификаторам

## Новый принцип выделения

Программа сама разбивает текст требования на предложения/абзацы и формирует
каталог с локальными ID F001, F002 и далее. Каждый источник хранит исходный
текст и координаты start/end в символах Python (не байтах). Деление сохраняет
написание, числа, знаки, пробелы внутри фрагментов и идентификаторы.

Модель возвращает только описание, категорию и ссылки:

```json
{
  "elements": [
    {"type": "действие", "description": "Вернуть STATUS_OK", "source_ids": ["F001"]}
  ],
  "specification_gaps": []
}
```

Она больше не копирует цитаты. Подстановка текста происходит в приложении.
Один источник может подтверждать несколько самостоятельных элементов.
Допускаются несколько источников на элемент. ID действуют только внутри
текущего требования и его текста; ID из чужого каталога не принимаются.

## Что сохраняется и показывается

У элемента сохраняются source_refs с точными фрагментами и координатами.
Поле source_fragment оставлено для совместимости: это точный участок исходного
текста от первого до последнего выбранного источника. При несмежных ссылках
этот участок включает промежуточный контекст; выбранные источники отдельно
перечислены в source_refs и в полном просмотре элемента.

Проверки фактов используют именно выбранные источники, а не промежуточный
контекст. Ссылки и координаты сохраняются в SQLite и на листе Elements отчёта.
Старые SQLite-проекты без source_refs открываются как раньше; автоматическое
приписывание им новых источников не выполняется. Повторное выделение создаёт
ссылки заново и сбрасывает старые связи покрытия с предупреждением.

При ручном изменении текста источника устаревшие source_refs очищаются:
такой элемент сохраняет ручную цитату и прежнюю проверку её наличия в тексте.
Изменение только описания не стирает ссылки, но сбрасывает зависимые решения.

## Что упрощено

Удалено специальное правило удаления «компонент должен» из выдуманной цитаты
и повторные запросы ради перепечатывания текста требования. Теперь это может
быть частью свободного описания, а источник всё равно берётся из каталога.
Неверные ID, дубли, неправильная структура и обнаруженные противоречия
обрабатываются ограниченным повторным запросом. Неверный старый контракт LLM
с source_fragment не принимается молча — модели объясняется новый формат.

Безопасная нормализация цитат тестовых доказательств в анализе покрытия
сохранена: это отдельный контракт, который данной переработкой не меняется.
При сравнении технических токенов нового элемента используется описание,
чтобы широкий источник не требовал от теста проверки всех других действий
того же предложения. Числовой контекст проверяется по выбранным источникам.

## Ограничения

Корректный ID доказывает происхождение текста, но не истинность описания.
Существующие проверки имён, чисел, известных противоречий и категорий сохранены,
как и ручная проверка. Программа не гарантирует семантическую полноту любого
естественного языка. Автоматическое деление — вспомогательное адресование,
а не готовое выделение проверяемых элементов.

После обновления откройте копию проекта, повторите выделение и проверьте
описания и ссылки в полном просмотре. Затем выполните покрытие и экспорт.
Ожидаемый результат для ошибки «компонент должен вернуть STATUS_OK» —
самостоятельное описание с ссылкой на предложение, где STATUS_OK задан;
перепечатывать точную сокращённую цитату модель больше не должна.

## Замечания к структуре без остановки анализа

Объединённое условие/действие или несколько независимых результатов —
замечание качества разбиения, а не выдуманный факт. Такие элементы сохраняются
с review_notes и статусом «ожидает проверки»; замечания видны в полном просмотре,
анализе и XLSX. Повторные запросы только из-за этих двух замечаний не выполняются.
Пользователь может уточнить описание или принять обоснованное разбиение.
Выдуманные имена/числа/ограничения и неизвестные источники по-прежнему блокируются.
Сами замечания и успешное завершение не подтверждают покрытие автоматически.

## Явные перечисления проверяемых действий

Модель инструктируется формировать один предикат на элемент. Дополнительно
единое правило разбиения распознаёт перечисления поддерживаемых действий,
соединённых «и», «а также» или точкой с запятой: сохранить, вернуть, установить,
сбросить, вызвать и другие явно перечисленные предикаты. Оно не делит союзы
внутри аргументов и числовых условий.

«Сохранить value в currentLevel и вернуть STATUS_OK» даёт два действия.
В явной форме «Если ..., компонент должен вернуть ... и оставить ...»
сохраняется отдельное общее условие и отдельные проверяемые результаты.
Неизменность значения определяется как ограничение. Все элементы ссылаются
на те же исходные фрагменты и остаются на ручной проверке, без автоматического
подтверждения покрытия. Изменение числа элементов меняет знаменатель покрытия.

При нераспознанной грамматике, вложенном условии или явном отрицании разбиение
не угадывается. Сохраняется исходное предложение с существующими замечаниями,
а не придумывается преобразование. Это не полный синтаксический анализ русского
языка и не доказательство корректности любого перечисления.

## Условия применимости и ветви

У элемента есть `condition_ids` (все перечисленные условия истинны) и
`negated_condition_ids` (все перечисленные условия ложны). Это ссылки на
самостоятельные элементы категории «условие» того же требования.
Они сохраняются в SQLite, экспортируются в Elements, показываются в полном
просмотре и редактируются флажками в редакторе элемента. Изменение связей
сбрасывает прежний анализ требования. Противоречивые ссылки и циклы запрещены.

Общий разбор простых конструкций «Если …, [то] …», «При … должен …»
в выбранном источнике добавляет пропущенное явное условие и связывает с ним
действия/ограничения. Имена функций, переменных, констант и требования не заданы
в правилах. Для «иначе» используется отрицание того же условия, а не выдуманное
новое поведение. Сторона ветви выбирается только при однозначном совпадении
описания действия с одной из частей источника.

Вложенные конструкции, несколько условных источников и неоднозначная сторона
«иначе» не связываются автоматически: сохраняется замечание для проверки.
Разбор не заменяет полноценный синтаксический анализ естественного языка.
Если модель не выделила само действие, правило не восстанавливает его из
догадки. Проверьте полноту выделенных аспектов и применимость вручную.

Контекст передаётся в семантический анализ покрытия и генерацию тестов.
Отклонённое условие требует уточнения зависимого аспекта и препятствует
положительному автоматическому предложению покрытия. Все связи покрытия
по-прежнему подтверждает пользователь; процент после выделения может измениться
из-за добавления ранее пропущенных условий. Старые проекты открываются с пустыми
списками связей: для автоматического заполнения повторите выделение на копии.
