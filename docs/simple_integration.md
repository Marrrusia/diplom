# Простое выделение внутри проекта — 0.5.2rc1

## Что встроено

Вместо каталога источников и ответа elements модель получает исходный текст одного требования и простую схему:

- obligations: statement, conditions, source_fragment;
- specification_gaps.

На каждое требование вызывается выделение один раз. Некорректный JSON не переписывается повторными запросами. Инфраструктура ожидания HTTP 429 из предыдущей сборки сохранена: она не исправляет содержание ответа.

Каждое обязательство становится одной строкой проекта. Порядок и разбиение модели сохраняются. Условия не преобразуются в граф отдельных элементов и могут быть сформулированы своими словами. Программа не проверяет их дословное совпадение и не дописывает пропущенный общий вызов. Пустые conditions остаются пустыми и требуют внимания пользователя.

Автоматической классификации по шести категориям нет. Новые строки получают нейтральный тип «обязательство». Старые категории и связи сохраняются для совместимости старых проектов; при необходимости категорию можно выбрать вручную в редакторе. Полного автоматического соответствия исходному пункту ТЗ о шести категориях эта сборка не заявляет.

## Где используются условия

В таблице элементов появилась колонка «При каких условиях». Условия доступны в подробностях, в редакторе и на листе Elements отчёта XLSX. SQLite сохраняет их вместе с элементом.

Анализ покрытия получает их в applicability.all_true и в самом элементе. Генерация и её проверка получают текстовые conditions в моделях элементов. Это передача контекста, не гарантия правильного семантического решения модели.

При изменении условий сбрасывается зависимое покрытие и подтверждение полноты. При повторном выделении отвергнутые сгенерированные тесты не становятся принятыми или ожидающими проверки.

## Проверка цитат

Проверяются JSON-структура и дословное наличие source_fragment. Перефразирование statement и conditions не считается ошибкой. Проверка имён, чисел и смысла автоматически не заявляется.

Если цитата не найдена, строка остаётся видимой с замечанием, сохраняется в проект и диагностику. Она временно исключена из покрытия и целей генерации; принять её до исправления нельзя. Можно исправить цитату в редакторе либо отклонить строку. Программа не заменяет многоточия и не подбирает за модель другой источник.

Полнота всего набора остаётся неподтверждённой до ручной проверки. Пока она неизвестна, процент не определяется. Нельзя подтверждать полноту только ради появления процента.

## Проверка сборки

187 автоматизированных теста прошли: импорт, протоколы, интерфейс, сохранение/отчёт, редактирование, покрытие и генерация; новые тесты проверяют передачу условий по всему пути, один ответ выделения, отсутствие скрытого разбиения, исправление цитаты и блокирование неподтверждённой строки.

Три присланных пользователем ответа воспроизведены без обращения к модели:

| Ответ | Строки после импорта | Неподтверждённые цитаты |
|---|---:|---:|
| MODE | 5 | 0 |
| MASK | 3 | 0 |
| LOOP | 5 | 1: source_fragment с многоточием |

Смысл и полнота этими проверками не доказываются. У MASK пустые условия сохранены, а не автоматически исправлены. В LOOP разделение первого обязательства сохранено. Новых запросов к реальной модели при интеграции не выполнялось.

Тесты старого JSON-контракта source_ids и его автоматического разбиения сохранены в historical_tests как текстовые файлы. Они описывают заменённый механизм и не входят в актуальный запуск pytest. Проверки импорта, хранения, покрытия, генерации, интерфейса и атомарности сохранены; тесты полного рабочего цикла переведены на новый формат. Количество тестов нельзя сравнивать с предыдущими версиями как показатель качества модели.

## Запуск

1. Распаковать в отдельную папку, открыть diplom в PyCharm, выбрать Python 3.11+.
2. Установить зависимости: python -m pip install -e ".[dev]".
3. Запустить Ollama. Модель qwen35-9b-q5:latest должна присутствовать в ollama list.
4. Запустить main.py, в настройках выбрать ollama / http://localhost:11434 / qwen35-9b-q5:latest. Ключ пустой.
5. Создать новый проект, импортировать только нужные требования и выделить элементы. Начать с MODE и MASK из examples/demo_suite.
6. Проверить условия и цитаты, при необходимости отредактировать. Исходный ответ остаётся в автоматической диагностике.

После запуска диагностика сохраняется в %USERPROFILE%\.reqtest\logs (либо REQTEST_LOG_DIR) под именем extraction-diagnostics-…json; формат simple-obligations-project-1, версия 0.5.2rc1.

Старый проект открывается с сохранением прежних категорий и связей, новые поля получают безопасные значения по умолчанию. Не смешивайте старое выделение с новым при сравнении. Сохраняйте проект под новым именем: предыдущие версии могут не понимать новые поля и тип «обязательство».

## Исправление 0.5.2rc1

Пустые строки в списках доказательств покрытия рассматриваются как отсутствие доказательства. Они не вызывают повторные запросы и не останавливают анализ. Если модель предлагает покрытие без цитаты действий или ожидаемого результата, решение переводится в «требует проверки». Непустые неверные цитаты проверяются по прежним правилам. Промпт выделения и его результаты не менялись. Проверены пустые/пробельные строки, сохранение настоящих цитат рядом с пустыми и продолжение следующих пар.

## Диагностика покрытия в 0.5.2rc1

Промпт, выбор пар, проверка цитат и вычисление статусов покрытия не изменены. При каждом запуске создаётся coverage-diagnostics-ДАТА-ВРЕМЯ-ID.json в %USERPROFILE%\.reqtest\logs (либо REQTEST_LOG_DIR). Файл сохраняется и при неудаче.

Содержимое: требования, элементы, тест-кейсы, модель, полные сообщения запросов и схема, исходный ответ каждой попытки, ID текущей пары, разобранный ответ до проверки, provided_fields (реально присутствовавшие поля), ответ после проверки цитат, причины и итоговое решение. Так можно отличить отсутствующее result_evidence от явно пустого массива и от изменения при обработке. HTTP-заголовки и адрес не экспортируются; известный клиенту ключ маскируется. Тексты требований и тестов присутствуют.

182 теста прошли. Новых запросов к модели не выполнялось. Для разбора текущей проблемы повторите только CRC / TC_CRC_001 и пришлите самый новый coverage-diagnostics-…json. Статус completed в диагностике означает завершение обработки, а не подтверждённое покрытие.
