# Проверка проекта по техническому заданию — 19 октября 2026

Это отчёт первичного аудита версии 0.1. Актуальная переработка и проверки 0.2.0:
[extraction_v2.md](extraction_v2.md), [validation_v2_results.md](validation_v2_results.md).

Проверена версия `068be77c15b01b5260ba679ef6fb723ee5456a2a` и исправления
этого аудита. Приложение имеет все основные слои и сценарии ТЗ; переписывание
с нуля или удаление функциональных разделов не требуется. Ниже отделены
реализованные механизмы от того, что требует испытаний с настоящей моделью.

## Найдено и исправлено

1. **Отклонённые тесты возвращались на проверку.** Изменение текста требования,
   правка/проверка элемента и повторное выделение меняли статус отклонённых
   сгенерированных тестов на ожидающий. Теперь отклонение сохраняется.
   Принятые предложения по-прежнему требуют повторной проверки при изменении
   основания анализа. Явное редактирование самого теста может открыть его заново.
2. **DOCX искажал текст.** Сборка текста из узлов `w:t` теряла переносы и табуляцию;
   абзацы внутри ячеек сливались. Импорт теперь использует `Paragraph.text` и
   сохраняет границы абзацев ячеек. Это предотвращает склейку технических имён.
3. **Отклонённые элементы ошибочно объявлялись покрытыми в запросе генерации.**
   Список `covered_element_ids` строился как дополнение к целям, включая
   исключённые аспекты. Теперь туда попадают только активные элементы с
   подтверждёнными положительными связями с активными тестами.
4. **Дополнена защита обработчиков от изменений во время фоновой операции.**
   Импорт, редактирование требования, ручное решение по связи и проверка
   сгенерированного теста теперь проверяют занятость сами. Кнопки уже блокировались;
   новая защита также покрывает прямой/повторный вызов обработчика и предотвращает
   применение изменений к снимку, который будет заменён результатом потока.

Добавлены 11 параметризованных регрессионных проверок. На исходном коде все
11 завершаются ошибкой; на исправленном проходят вместе с остальным набором.

## Соответствие ТЗ

| Область | Что найдено | Практический предел проверки |
| --- | --- | --- |
| Python 3.11+, слои | `pyproject.toml`, отдельные ui/models/services/llm/storage/importers/exporters/tests | Проверен Python 3.12; другие версии требуют своего запуска |
| Требования TXT/DOCX/XLSX | Импорт, ID, метаданные, просмотр и изменение текста | Формат документа должен соответствовать руководству; DOCX исправлен в этом аудите |
| Шесть типов элементов | Pydantic, ссылки на исходные фрагменты, проверка цитат, повторные запросы | Наличие цитаты не гарантирует смысловую правильность описания |
| Тесты CSV/XLSX | Предпросмотр и сопоставление колонок, проверка уникальности и ссылок | Тест связан с одним требованием |
| Гибридное покрытие | Точные технические токены, LLM, цитаты доказательств и проверки противоречий | Естественный язык не проверяется формально; эвристики ограничены |
| Матрица и проценты | Три статуса, проценты по требованиям и набору, ручные решения отдельно | Процент относится к выделенным активным элементам |
| Два режима генерации | Первоначальный набор и дополнение; структура, дубликаты, отдельный запрос проверки | Полнота и качество реальной генерации зависят от модели |
| Ручная проверка | Правки элементов/тестов, принятие/отклонение, сброс устаревшего покрытия | Исправлено сохранение отклонений при изменении контекста |
| XLSX | Шесть листов, начальная/итоговая статистика, журнал и обоснования | Исходный процент неизвестен, если снимок не был зафиксирован |
| Интерфейс | Семь русских разделов, прогресс, отмена, QThread для LLM и сохранения | Импорт больших файлов остаётся синхронным и может задержать окно |
| SQLite | Валидированный снимок, атомарная запись и проверка версии | Полной истории редакций и автосохранения нет; ТЗ их не требует |
| Секреты и ошибки | API-ключ исключён из проекта, HTTP-ошибки скрывают содержимое ответа | Защита не распространяется на секреты, введённые пользователем в текст требования |
| Демонстрация CRC | Пример и проверки; отрицательный сценарий не задаётся как требуемое поведение | Требуется демонстрация с настоящим Ollama и ручной экспертизой |

## Что сохранено и что ещё проверить

Функциональные разделы, демонстрационные данные, SQLite и XLSX не удалялись.
Матрица, ручная проверка и валидация нужны для заявленной темы ВКР. Убирать их
ради упрощения интерфейса было бы потерей требований задания.

До защиты нужно выполнить ручной протокол `docs/validation.md` с настоящим
Ollama: зафиксировать модель, входные документы, ответы, ручные исправления,
показатели до/после и итоговый отчёт. Тесты с подменённым HTTP не измеряют
качество LLM. Проверка генератором той же модели не является независимой
экспертной оценкой. PyCharm, масштабирование экрана и выполнение тестов на
встроенном устройстве этим аудитом не проверены.

Следующая полезная доработка для больших документов — перенос импорта в
фон и предварительная оценка числа запросов покрытия. Для текущего небольшого
демонстрационного сценария они не требуют изменения архитектуры и не должны
подменять проверку качества анализа на реальных требованиях.
