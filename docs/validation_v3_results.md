# Фактические проверки 0.3.0 — 21 октября 2026

## Код

196 автоматических проверок проходят. Схема старой обязательной экспертизы и
связанные с ней тесты заменены проверками одностадийного контракта: четыре поля,
назначение ID приложением, цитаты/исправление с конкретной диагностикой, текстовая
применимость, частичный результат, отмена, сохранение ответов, SQLite, XLSX и UI.
Сохранились проверки импорта, покрытия, генерации и HTTP обоих провайдеров.
Прогон корпуса на подменённых ответах: 12/12 операций. Это не оценка качества.

Windows 11, Python 3.12.14, PySide6-Essentials 6.7.3. Проверка запуска/закрытия
окна выполнена в offscreen-режиме. Реальная модель доступна через Ollama,
qwen2.5:7b, Q4_K_M, 7.6B, CPU, контекст работающего сервера 4096.

## Выявленные недостатки результата

- RANGE: запись и возврат STATUS_OK разделены, однако отрицательная ветвь всё ещё
  объединяет возврат ошибки и неизменность поля. У входного условия перепутан
  контекст с описанием эффекта. Разбиение и классификация неполны.
- MODE: модель трижды вернула несуществующую цитату «возвращает STATUS_NOT_READY»
  вместо исходного «вернуть STATUS_NOT_READY». Этот кандидат не получил выдуманной
  цитаты; частичный результат и ошибка сохранены. Вызов ReadADC и возврат значения
  остаются объединены. Неопределённое поведение ошибочно попало в ограничение.
- LOOP: представлены повторение, предел, остановка после успеха и возвращаемые
  статусы; применимость следует сверить с исходником вручную.
- TIME: ветви различаются в контексте, но вызов, отсутствие аргументов и число
  вызовов остаются одним составным элементом.
- MASK: формула и сохранность битов выделены, но присваивание битов внутри маски
  классифицировано как ограничение вместо действия.
- AMBIG: модель создаёт «диапазоны» без заданных значений и предлагает аспекты,
  для которых спецификация не задаёт критерии проверки. Эти предложения следует
  отклонить/исправить, а недостаточность спецификации сохранить как замечания.

Следовательно, исправлена сложность протокола и обработка ответов, но качество
автоматического выделения этой моделью пока недостаточно для использования без
ручной проверки. Успешные тесты и отсутствие блокировки не выдаются за решение
семантических ошибок. Настройки/модель влияют на качество; их изменение требует
нового измерения. Тест-кейсы на настоящей модели в этом прогоне не генерировались.

## Два новых требования вне прежнего демонстрационного набора

Прогон того же механизма на IRQ (английское требование к захвату таймера и
подтверждению прерывания) и STATE (два состояния с двоеточиями вместо оборота
«в режиме») выполнен через настоящую модель. Обе операции завершились, но
смысловое качество недостаточно: у IRQ подтверждение прерывания неточно передано
как «Узнать прерывание», а порядок операций не выделен отдельно. У STATE контекст
SLEEP ошибочно связан с ветвью RUN, и у одного режима указан контекст другого.

Реальные ответы: `examples/model_runs/qwen2.5-7b-novel-2026-10-21.json`.
Эталоны не отправлялись модели. Наблюдения подтверждают, что одной упрощённой
структуры ответа недостаточно для семантической правильности выбранной модели.
