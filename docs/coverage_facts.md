# Независимая проверка фактов покрытия

Модуль `coverage_facts` не вызывает LLM и не исполняет выражения из документов.
Он проверяет ограниченную явную грамматику числовых условий: меньше/больше,
равно/не равно, сравнения с равенством, операторы <, >, <=, >=, ==, !=,
включительный диапазон, союзы «и», «или» и явный эллипсис имени параметра.
Поддерживаются отрицательные числа и десятичная точка/запятая.
Неизвестная конструкция, скобки, отсутствующий или нечисловой вход дают
«неизвестно», а не ложь. Имена функций, параметров и статусов не зафиксированы.

Истинность проверяется по описанию самостоятельного условия, связанному с
элементом через condition_ids/negated_condition_ids. Простое условие вызова
проверяется по явному действию вызова в тесте. Широкая цитата условия вызова
не добавляет к нему диапазон из соседних аспектов.

Для ограничения «оставить <поле> без изменения» сравниваются однозначные
присваивания из предусловий и ожидаемого результата. Числовые 3 и 3.0 равны.
Несколько различных значений одного поля и отсутствие значения не доказывают
неизменность. Это проверка содержания тест-кейса, не фактический запуск ПО.

Факты передаются модели и сохраняются в обосновании. При противоречии
положительного решения вычисленному условию или сохранности состояния
результат становится «требует проверки». Отрицательный вывод также переводится
в проверку, если явно выполнено условие или при выполненной применимости
найден соответствующий возврат статуса/неизменность поля. Это не исправляет
решение на «покрыт» и не утверждает корректность всего теста. Даже тест с
ошибочным ожидаемым результатом может выполнять условие входа; такой конфликт
разрешается проверкой всего сценария пользователем, а не автоматическим зачётом.

Проверки не доказывают полноту диапазона и не заменяют ручную проверку.
При неподдерживаемой формулировке используются прежний семантический анализ и
его ограничения. Старые результаты не переписываются при открытии проекта:
после обновления повторите анализ покрытия на копии проекта.
