# Изменения 0.3.7

Пересказы предпосылок модели с явными context_ids заменяются дословными
условиями каталога, если не обнаружены сигналы результата или недостаточности
спецификации. Одинаковые дословные условия объединяются, противоположные
ссылки после объединения отклоняются. Смысловая эквивалентность разных
формулировок произвольно не устанавливается.

Если в выбранном фрагменте отсутствует имя из описания, допускается добавление
единственного явного определения «имя по формуле» из того же требования при
наличии общих имён операндов. Ссылка и замечание сохраняются. Это ограниченное
восстановление определения, не разрешение использовать произвольные имена
и числа из всего требования; смысловую связь нужно проверить вручную.

Отрицание условия, содержащего вызов функции, блокируется для ручной проверки:
программа не преобразует отрицание составной предпосылки по догадке. Результаты,
ошибочно названные условиями и распознанные по ограниченному набору глаголов,
также отмечаются. Чистые сообщения об отсутствии спецификации исключаются
из элементов и сохраняются в замечаниях. Смешанные предложения остаются
предметом ручной проверки.

Короткая инструкция дополнена правилами не дублировать каталог условий,
ссылаться на определение и не придумывать новые пробелы. Замечания модели
по-прежнему могут быть ошибочными; они не становятся требованиями.

Проверка на сохранённой пользовательской диагностике Qwen (без сетевых вызовов):
MASK — четыре элемента, включая один узел условия; MODE — пять результатов
и четыре условия. Ошибок ID и блокировок в этих двух обработанных ответах нет.
Это проверка нормализации двух прежних ответов, не доказательство качества
новых ответов модели или полноты выделения произвольных требований.

Регрессионные проверки охватывают дословные условия, добавление определения,
отказ от посторонних имён/чисел, отрицание составного контекста, результат
вместо условия и исключение недостаточности спецификации. Настройки моделей
не изменены. Ожидание при HTTP 429 в эту версию не добавлено.
