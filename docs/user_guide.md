# Руководство пользователя

## Проект и импорт

«Файл → Новый проект» создаёт отдельный набор данных. Ctrl+S сохраняет SQLite,
Ctrl+O восстанавливает проект, Ctrl+Shift+S сохраняет отдельную копию.
Звёздочка означает несохранённые изменения. Автосохранения нет. Перед сменой
версии приложения сохраните проект и резервную копию файла.

Требования поддерживают TXT/DOCX/XLSX; тесты — CSV/XLSX. Сначала загрузите
требования, затем тесты. Дубликаты ID, неизвестные ссылки и неправильные строки
отменяют весь импорт без потери ранее загруженных данных.

- TXT: UTF-8, блоки через пустую строку или `ID: текст`. Без ID назначается
  REQ-0001 и далее. Строка «Слово: текст» считается новым требованием.
- DOCX: тот же формат абзацев; таблицы без заголовка, две колонки ID | текст.
  Сложную структуру сначала приведите к этому формату.
- XLSX: выберите лист; первая непустая строка — уникальные непустые заголовки.
  Формулы замените значениями до импорта.
- CSV: UTF-8 или Windows-1251; разделитель определяется для запятой, точки
  с запятой или табуляции. Многострочные ячейки должны быть в кавычках.

Требования: обязательны id/text; type/source необязательны; остальные колонки
сохраняются как metadata. Тесты: обязательны id, requirement_id, title, steps,
expected_result. Предусловия/действия разделяются переводами строк внутри
ячейки. Входные данные — текст либо JSON-объект со строковыми значениями.
В диалоге сопоставьте поля и проверьте предварительный просмотр.

## Выделение и ручная проверка

Укажите сервер/модель в «Настройки LLM». В «Проверяемые элементы» запустите
выделение. Категории: условие, действие, ограничение, диапазон, цикл, режим.
Программа нумерует исходные предложения/абзацы. Модель возвращает описания
со ссылками на их ID; источник подставляется самим приложением и может быть
шире отдельного элемента. Ссылки и точные координаты видны в полном просмотре.
Для старых проектов без ссылок сохраняется прежняя ручная цитата; повторное
выделение создаёт новый формат и сбрасывает старые решения покрытия.
Смысл описания проверяет пользователь.

Выбор строки показывает полный текст. Поиск фильтрует отображение и не меняет
данные. Для исправления выберите «Редактировать выбранный элемент».
Отклонённые элементы остаются видимыми, но исключаются из матрицы и знаменателя;
их количество показывается отдельно. Не отклоняйте правильный аспект ради процента.

В примере CRC должны быть отдельно: вызов HAL_CRC_MspInit, Instance == CRC,
включение тактирования через макрос и вызов без аргументов. Для Instance != CRC
нет заданного поведения; отрицательный ожидаемый результат выдумывать нельзя.

## Покрытие

Запустите «Матрица покрытия → Анализировать покрытие». Пара анализируется,
если ID требования совпадает. Отклонённые тесты и непринятые сгенерированные
тесты не участвуют. Технические имена и числа проверяются детерминированно;
семантический вывод требует соответствующих действий и ожидаемого результата.

В ячейке доступны предложение модели, уверенность, цитаты и проверки.
Положительное предложение до принятия отображается «требует проверки».
При ручной проверке выберите собственный статус и содержательное обоснование.
Ручное решение хранится отдельно от решения модели. Одного слова «покрыт»
недостаточно для качественного обоснования, даже если поле технически непустое.

Процент = активные элементы с хотя бы одной принятой положительной связью /
все активные выделенные элементы. Пустой знаменатель — «не определено».
Результат описывает содержание тестов, не их успешное выполнение на устройстве.

## Генерация и редактирование тестов

- Первоначальный набор: только когда в проекте вообще нет тестов.
- Дополнение: элементы без подтверждённого покрытия. При 4/4 запросов нет.

Проверьте полный текст предложений и журнал. Структура, ссылки, известные
противоречия и точные дубликаты проверяются программой; семантическая проверка
выполняется дополнительным запросом к модели. Это не гарантия корректности.

Редактор теста содержит отдельные поля; JSON нужен только для входных данных,
например `{"crcHandle.Instance": "CRC"}`. ID/источник/требование остаются
неизменными. Тест вызывает входную функцию, наблюдает действия компонента
и проверяет результат; он не должен сам выполнять действие компонента.

После правки тест возвращается на проверку, его старые связи удаляются.
Примите подходящий тест и повторите покрытие. Отклонённые предложения хранятся
для просмотра, но не входят в утверждённый набор. Изменение элемента сбрасывает
покрытие всего его требования; повторное выделение сбрасывает все связи и
возвращает сгенерированные тесты на проверку. Предупреждения объясняют сбросы.

## Отчёты и операции

Ctrl+E экспортирует текущий снимок в XLSX: Requirements, Elements, TestCases,
CoverageMatrix, Summary, GenerationLog. TestCases содержит неотклонённые
существующие и принятые сгенерированные тесты. Под матрицей — решения и обоснования.

Исходное покрытие фиксируется перед первой генерацией новой версии. Для старых
проектов может быть «не зафиксировано»; программа не заменяет неизвестное нулём.
При изменении оснований сравнения исходный снимок сбрасывается. Итоговый процент
вычисляется по текущим принятым связям.

Экспорт не заменяет сохранение SQLite. SQLite хранит также отклонённые/ожидающие
тесты, замечания анализа и журнал. API-ключ и настройки сеанса не сохраняются.

Анализ/генерация/файловые операции идут в фоне. Прогресс виден внизу всех вкладок.
Отмена LLM действует после текущего HTTP-запроса/таймаута. Файловая запись
завершается атомарно и не прерывается кнопкой отмены. Изменение данных во время
работы заблокировано. При ошибке проект в памяти не заменяется частичным результатом.
