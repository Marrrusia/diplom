# Пересмотр программы — 0.4.0rc1

Это проверочная сборка на основе diplom-branch-context. Предыдущие архивы не изменены. Новая инструкция ещё не проверена свежими ответами локальной модели: нельзя считать качество выделения улучшенным только по тестам кода.

## Выводы по слоям

| Участок | Найдено | Изменено |
|---|---|---|
| Импорт | Повторный импорт того же файла заканчивался общей ошибкой уникальности | Идентичные записи пропускаются; конфликтующие ID и дубли внутри файла отклоняются атомарно |
| Промпт | Смешивались инструкции и автоматические подсказки аспектов, включая раньше неопределённые ветви | Инструкция сокращена; aspect_hints убраны из запроса; потребованы отдельные результаты и все подтверждающие источники |
| Проверка ответа | Ошибка одного элемента блокировала всё требование; поздняя коррекция могла испортить ранний ответ | Сохраняется лучший набор прошедших проверку предложений; отвергнутые элементы и причины остаются в диагностике и замечаниях |
| Неопределённость | Из сообщения о пробеле получались проверяемые элементы | Чистые сообщения о неопределённости переводятся в замечания до проверки описания; смешанные предложения не отбрасываются целиком |
| Покрытие и генерация | Частичный набор мог выглядеть полным; отклонённые тесты возвращались в очередь при повторном анализе | До ручного подтверждения полноты процент не определён; отклонённые тесты остаются отклонёнными; исходный процент не фиксируется при неизвестной полноте |
| SQLite и XLSX | Полнота набора не сохранялась отдельно | Новый признак сохраняется; старые файлы открываются только для чтения с непроверенной полнотой; XLSX содержит пояснение |
| LLM и интерфейс | HTTP 429 немедленно завершал операцию общей ошибкой | До двух повторов с ожиданием по числовому Retry-After или сообщению try again in …s; одна пауза не более 60 секунд; отсчёт и отмена в рабочем потоке |

JSON-схема, проверка ID и проверка имён не доказывают семантическую корректность. Подсказки missing_aspects остаются ограниченными проверками известных конструкций, а не универсальной проверкой полноты. Повторные запросы сохранены до трёх попыток; при неудачной коррекции возвращается лучший проверенный набор, если такой есть. При полностью непригодном ответе, сетевой ошибке или отмене исходный проект не подменяется. При частичном успехе нескольких требований предыдущие элементы неудавшегося требования сохраняются как непроверенные.

## Проверка на сохранённых ответах

Использованы два пользовательских запуска одного MODE-требования, без обращения к LLM и без исправления сохранённых ответов вручную.

- Ответ qwen2.5:7b: получен набор на ручную проверку, семь элементов после обработки, один запрос воспроизведения.
- Ответ qwen35-9b-q5:latest: получен частичный набор, одиннадцать элементов после обработки, три ответа воспроизведения. Элемент StartADC с упоминанием ReadSample исключён из-за неполного источника; ошибка видна в замечаниях. Это не полный корректный результат.

Эти числа включают условия и ограничения, не являются оценкой полноты или точности модели. Записи из 0.3.7 с другим JSON-контрактом не используются как совместимые ответы старой ветки.

Автотесты проверяют импорт, отклонение выдуманных фактов, частичные результаты, исходный неизменяемый проект, отмену, протокол LLM, ручную проверку полноты, сохранение, отчёты и основной сценарий от импорта до генерации. В интеграционных тестах полнота подтверждается отдельным ручным действием, а не самим вызовом анализа.

## Что остаётся ограничением

- Полнота произвольных требований автоматически не доказывается. Смысловые ошибки и пропуски модели возможны.
- Привязка ветвей основана на ограниченном синтаксическом разборе. Вложенные условия, общий контекст нескольких предложений и порядок действий требуют проверки.
- Разделение действий использует небольшой словарь; сложные конструкции не гарантированно атомарны.
- Модель может выбрать неполные source_ids. Программа не добавляет произвольный контекст всего требования, чтобы скрыть такую ошибку.
- Числовое и семантическое покрытие по-прежнему требует проверки каждого решения; прежние ошибки модели при сопоставлении тестов не объявляются исправленными.
- Лимит с ожиданием более минуты не обходится: приложение сообщает длительность и прекращает операцию. Ограничение ответа по токенам и длительные фоновые задания не добавлены.
- Отмена текущего HTTP-запроса ожидает его тайм-аут; отмена паузы 429 проверяется часто.

## Как проверить сборку

1. Распаковать в отдельную папку, открыть её в PyCharm. Зависимости — из pyproject.toml, запуск — main.py.
2. В Ollama должна быть уже установлена qwen35-9b-q5:latest. Выбрана она, адрес http://localhost:11434, ключ пустой. Веса не включены и не менялись.
3. Выделить элементы MODE и MASK. В замечаниях проверить не только ошибки, но и пропущенные обязательства исходного текста.
4. Исправить элементы, принять/отклонить предложения. Кнопка «Подтвердить полноту требования…» требует принятия всех активных элементов и обоснования проверки полного исходного требования. Не подтверждать полноту ради появления процента.
5. При редактировании полнота снова становится непроверенной. Полнота не равна подтверждённому покрытию тестами.
6. Диагностика сохраняется автоматически в %USERPROFILE%\.reqtest\logs, имя extraction-diagnostics-…json. Адреса и заголовки не записываются, известный клиенту ключ маскируется. Тексты требований в файле присутствуют.

Сохраните проект под новым именем: старые приложения могут не понимать добавленное поле полноты. Для выводов о новом промпте ещё нужен небольшой одинаковый набор требований с ручным эталоном и реальный прогон модели. Публикация на GitHub не выполнялась.
