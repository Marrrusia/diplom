# Проверки и демонстрация

## Автоматические проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pytest -q -m integration
.\.venv\Scripts\python.exe -m pip check
```

Для отчёта используйте `--junitxml=test-results.xml`. Автоматические тесты не
требуют сервера: они подменяют HTTP-ответы LLM, используют реальные сервисы,
SQLite/XLSX и окна Qt. `scripts/verify_windows.ps1` дополнительно проверяет
настоящую точку входа и управляемое завершение GUI. Проверки запускаются с
QT_QPA_PLATFORM=offscreen, а рабочее окно — без этой переменной.

операции как успешные. Для ВКР сохраните версии Python, пакетов, Ollama, модель,
характеристики компьютера и JUnit-отчёт. Реальные ответы моделей могут различаться.

## Сценарий защиты ВКР

1. Покажите исходное требование SDD_MVA_INIT_F_00040 и его явно заданные аспекты.
2. Загрузите существующий пример теста. Покажите подтверждение покрытия по
   цитатам действий/предусловия/результата; объясните, почему 1.0 модели не
   заменяет ручную проверку.
3. Покажите, что при полном подтверждённом покрытии дополнение ничего не генерирует.
4. Создайте новый проект, импортируйте только требование и выполните полную
   генерацию. Проверьте сценарий: компонент вызывает макрос, тест наблюдает
   действие; ожидаемый результат содержит требуемый эффект.
5. При необходимости исправьте сценарий в редакторе. Примите тест, повторите
   анализ и проверьте связи. Не ожидайте одинакового ответа модели во всех запусках.
6. Сохраните SQLite, откройте его повторно и экспортируйте XLSX. Покажите
   восстановленные обоснования и начальный/итоговый процент, если исходный снимок известен.
7. Объясните ограничения: нет проверки поведения при Instance != CRC без
   спецификации; оценка не запускает тест на микроконтроллере.

Для повторяемой демонстрации сохраните уже проверенный SQLite-проект.
Он позволяет показать результат без повторной генерации и зависимости от сети.
Отдельно демонстрируйте работу настоящего Ollama, если сервер доступен.

## Статус проверок разработчика

Фактические результаты облачного запуска записаны в
[validation_results.md](validation_results.md). Проверки Windows и настоящего
Ollama этим агентом не выполнены. Пользовательские скриншоты предыдущих этапов
показывают работу основного сценария, но не заменяют весь протокол выше.
