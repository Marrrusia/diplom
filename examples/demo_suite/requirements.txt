DEMO_RANGE_001: При вызове SetLevel с целочисленным аргументом value в диапазоне от 0 до 100 включительно компонент должен сохранить value в поле currentLevel и вернуть STATUS_OK. Если value меньше 0 или больше 100, компонент должен вернуть STATUS_RANGE_ERROR и оставить currentLevel без изменения.

DEMO_MODE_002: При вызове ReadSample в режиме STANDBY компонент должен вернуть STATUS_NOT_READY и не вызывать StartADC. В режиме ACTIVE компонент должен вызвать StartADC() без аргументов; если ADC_READY равно 1, вызвать ReadADC() без аргументов и вернуть прочитанное значение. Поведение в режиме ACTIVE при ADC_READY, отличном от 1, не определено.

DEMO_LOOP_003: При вызове RetrySend компонент должен вызывать SendFrame(frame) до получения результата SEND_OK, но не более 3 раз. После SEND_OK повторные вызовы SendFrame запрещены, RetrySend должен вернуть STATUS_OK. Если все 3 вызова завершились SEND_ERROR, RetrySend должен вернуть STATUS_SEND_ERROR.

DEMO_TIME_004: При вызове HandleTick, если elapsed_ms больше или равно 10, компонент должен вызвать PollSensor() без аргументов ровно один раз за этот вызов HandleTick. Если elapsed_ms меньше 10, PollSensor вызываться не должен. Правила изменения elapsed_ms данным требованием не задаются.

DEMO_MASK_005: При вызове UpdateFlags компонент должен вычислить new_flags по формуле (old_flags & ~0x0F) | (requested_flags & 0x0F). В результате биты вне маски 0x0F должны сохранить значения old_flags, а биты внутри маски должны принять значения requested_flags.

DEMO_AMBIG_006: ProcessCommand должен быстро обрабатывать команды и корректно реагировать на некорректные входные данные. Список команд, критерии корректности, допустимое время и ожидаемые ответы в этой спецификации не указаны.
